# RideRadar

RideRadar is a Home Assistant HACS custom integration that recommends the best weather destination for spontaneous outdoor trips. The MVP focuses on motorcycle rides and uses Open-Meteo forecast data.

RideRadar does not rank destinations by straight-line distance. It uses a routing abstraction. The current MVP ships with a fallback route estimator that applies a configurable detour factor to direct geographic distance, so OSRM, GraphHopper, or OpenRouteService can be added later without changing the scoring and sensor model.

## Features

- UI config flow and options flow, no YAML-only setup
- Open-Meteo daily forecast polling every 3 hours through `DataUpdateCoordinator`
- Editable central destination area list
- Add, edit, disable, or remove destinations via the options flow JSON editor
- Per-destination RideScore per day
- Fallback route distance and travel time estimate
- Diagnostics support with start address redacted
- No paid API dependency

## Sensors

RideRadar creates these summary sensors:

- `sensor.rideradar_best_destination`
- `sensor.rideradar_best_score`
- `sensor.rideradar_best_day`
- `sensor.rideradar_best_summary`
- `sensor.rideradar_destination_count`

It also creates one distance sensor per enabled destination. Each destination sensor state is the route distance in km and includes attributes for:

- score per day
- explanation per day
- best day
- route distance km
- estimated travel time
- temperature
- precipitation probability
- precipitation amount
- wind speed
- wind gusts
- cloud cover
- weather code
- reachable
- explanation
- routing provider

Entity IDs are generated by Home Assistant from the RideRadar device and entity names. If a name collision exists, Home Assistant may add a suffix.

## Installation

### HACS custom repository

HACS requires a public GitHub repository URL. If this project is distributed from a GitHub mirror, add that GitHub repository URL in HACS. The Codeberg source URL is suitable for source browsing and manual installation, but may not be accepted by HACS.

1. Open HACS in Home Assistant.
2. Go to Integrations.
3. Open the three-dot menu and choose Custom repositories.
4. Add the public GitHub repository URL.
5. Select category Integration.
6. Install RideRadar.

### Manual installation

Copy `custom_components/rideradar` into your Home Assistant `custom_components` directory:

```text
config/
  custom_components/
    rideradar/
      __init__.py
      manifest.json
      ...
```

Restart Home Assistant after installing or updating the integration.

## Restart Home Assistant

In Home Assistant:

1. Go to Settings.
2. Open System.
3. Open Restart Home Assistant.
4. Choose Restart.

You can also restart from the command line if that is how your Home Assistant instance is managed.

## Add The Integration

1. Go to Settings.
2. Open Devices & services.
3. Select Add integration.
4. Search for RideRadar.
5. Enter a start address or explicit start latitude/longitude.
6. Set maximum route distance in km.
7. Set forecast days, usually `2` or `3`.
8. Keep activity profile as `motorcycle`.
9. Review destination areas JSON and submit.

If the start address cannot be resolved, enter latitude and longitude manually. RideRadar does not include or require any personal default address.

Coordinates are the stored source of truth after setup. In the options flow, clear both coordinate fields if you want RideRadar to geocode a changed start address again.

## Configure Destination Areas

Open the integration options to change all settings later:

- start address
- start latitude and longitude
- maximum route distance in km
- forecast days
- activity profile
- fallback detour factor
- destination areas

Destination areas are edited as JSON. Each item must include:

```json
{
  "name": "Eifel",
  "country_region": "Germany / Belgium",
  "latitude": 50.45,
  "longitude": 6.55,
  "enabled": true,
  "notes": "Optional note",
  "preferred_route_target_address": "Optional route target address"
}
```

To disable a destination, set `"enabled": false`. To remove one, delete that JSON object. To add one, append a new object with the same fields.

An empty destination list is valid. RideRadar will stay loaded and report that no enabled destinations are configured.

## Troubleshooting

- No best destination: increase maximum route distance or check that at least one destination is enabled.
- Address not found: enter explicit latitude and longitude in the integration options.
- Forecast unavailable: Open-Meteo may be temporarily unavailable; RideRadar will retry on the next update and Home Assistant will keep the previous successful coordinator data when available.
- Missing destination sensor after editing destinations: the options flow reloads the integration. If the entity registry still shows stale disabled entities, remove them from Settings > Devices & services > Entities.
- Distances look approximate: the MVP uses fallback route estimates. Tune the detour factor in options until a real routing provider is added.
- Invalid destination JSON: validate that the root value is a list and each item has `name`, `country_region`, `latitude`, and `longitude`.

## Architecture Notes

- `api.py` contains the async Open-Meteo client and normalizes API failures.
- `routing.py` defines `RoutingClient` and `FallbackRoutingClient`.
- `scoring.py` contains deterministic RideScore logic and activity-profile scoring thresholds.
- `coordinator.py` uses `DataUpdateCoordinator` and refreshes every 3 hours.
- `sensor.py` exposes summary and per-destination sensors attached to one RideRadar device.
- `diagnostics.py` exposes redacted config diagnostics.

Future routing providers should implement `RoutingClient.get_route()` and return `RouteInfo`. Future activity profiles should add profile-specific routing behavior and a matching `ScoringProfile` entry.
